# ホーム報告書（2026-11-27）

## 頼まれたこと
業務日報のホームを選ぶ画面に、報告書の入力フォームを新設する。入力は 日付・報告者・本文。
入れた内容を、法人の様式「ホーム報告書」（A4 縦）に反映して紙に出す。印刷するのは書いた職員。
様式右上の 管理者・サービス管理責任者・報告者 の枠は印鑑を押すので空白のまま。

## 決めたこと
- 入口：`index.html` に「📝 ホーム報告書を書く」→ `houkoku.html`
- 欄：日付（今日）・ホーム（様式の中央の欄に要るので足した。直前のホームを初期値）・報告者（覚えない）・本文（8000 字まで）
- 保存先：表 `home_reports`（`migrations/2026-11-27d_home_reports.sql`）。同じ日・同じホームに何枚でも
- 番号（id）は画面側で先に作る＝送り直しや 2 度押しで 2 枚にならない
- 直す時は「読んだ時の更新時刻」で絞る＝ほかの端末の直しを黙って上書きしない。更新時刻は DB が付ける
- 「消す」は行を消さない（`deleted_at` を入れて一覧から隠す）。ブラウザの鍵に行の削除は許さない
- 印刷：ブラウザの印刷。紙（`#sheet`）の寸法は様式の Word の数値どおり（列 62.4／75.2／15／15／15 mm・行 13.8／11.5 mm・罫線 0.5pt）
  - 「印刷する」は保存してから刷る。保存に失敗した時は確かめた上で刷れる（紙が目的）
  - 報告者の名前は本文の右上に「報告者：○○」。書体は UD デジタル 教科書体を先に指定し、無い端末は代わりの書体
- 書きかけ：端末の中に 3 日まで。開き直した時は黙って戻さず「いつの・誰の書きかけか」を見せて選ばせる
- 本文・名前は文字として入れる（HTML として解釈させない）

## 写真（同日追加）
オーナー「写真をアップロードできるようにして」→「報告書は本文のみ、写真は写真で大丈夫だから、別でいいよ」。
- 本文の下に「写真（4 枚まで）」。選ぶとその場で縮めて（長い辺 1600px・JPEG）送る。見本を押すと大きく見られる。✕ で外す
- **紙（印刷）には載せない。**紙は本文だけ
- 置き場は非公開の `home-report-photos`（`migrations/2026-11-27e_home_report_photos.sql`）。ログイン済みは 読む・足す だけ（上書き・削除は不可）
- 報告書の行には置き場の中の名前だけ（`photos = [{"path": …}]`）。見るための住所は期限つき（1 時間）で、開くたび・40 分ごとに作り直す
- 外した写真・保存しなかった写真は置き場に残る。画面からは消せない＝消したい時は Getter が DB から消す
- 刷るのは事務所のパソコン（オーナー回答）。入口は 2 つ＝日報の `index.html` と、管理画面のサイトの `/report/`（職員が使うのは後者）

## やらないこと
管理画面側の一覧／写真を紙に載せる／Word 出力／承認の流れ／利用者の選択欄／2 枚目の見出し

## 確認
- `node --test scripts/*.test.js`（計算部分）
- `python3 scripts/verify_home_report.py`（2 種類のブラウザ × 3 つの幅・DB は全部まね）
- `python3 scripts/verify_home_report.py --pdf <出力先>`（印刷の見た目。様式と罫線の位置を比べる）
- 実機の端末とプリンターで紙に出す確認は本番で行う（余白の指定を端末がどこまで守るかは実機でしか分からない）
