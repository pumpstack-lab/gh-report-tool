# 入浴の記録（マハロ） 設計書

2026-11-24 オーナー依頼・同日確定。対象はこもれびホームマハロ（gh_num=6）だけ。

## 1. 目的

夜勤の職員が、入浴の順番・開始と終了の時刻を日報で選んで残す。管理者はダッシュボードで「順番・時刻・かかった時間」を見る。平均や合計は出さない（オーナー決定「シンプルに順番と所要時間、時刻」）。

## 2. オーナー確定事項

- マハロに限る（ほかのホームには行を出さない・読み込みにも行かない）
- 順番は選択式。その日によって変わるので、番号だけ先に入れて時刻を後から入れられる
- 事業所で入浴する方がいるので、順番と同じ選択の中に「事業所で入浴」を 1 択で置く（事業所の名前は選ばない）
- 時刻は「何時から何時まで」を選択。分は 10 分刻み
- かかった時間は自動計算し、管理者ダッシュボードに出す
- 管理者画面の表のタイトルは「マハロの入浴状況」
- 検温の実機確認・速度改善より先に出す（急務）

Getter が足した点（オーナーに提示済み）：「入浴なし」の選択肢（未記入と区別する）／短期入所①②にも行を出す／Word 出力には入れない。

## 3. 画面（report.html・マハロだけ）

入居者と短期入所①②の各枠で、検温の下に「入浴」の行。

- 選択 1 つ目：選ぶ／1番〜N番／事業所で入浴／入浴なし。N＝入居者の数＋2（短期入所の枠）
- 「開始（時・分）」「終了（時・分）」は最初から見えている（番号を選ぶまで隠すと入れ方が分からない・オーナー指摘）。事業所で入浴・入浴なしの時だけ隠す。順番より先に時刻を選んだ時は保存せず「順番を選ぶと保存されます」と出す。時の並びは 15 時〜23 時→0 時〜14 時（日報 1 枚は前日の夕方〜当日の朝）
- 開始の「時」を選ぶと、空の終了の「時」だけ同じ時になる。分は自動で入れない（終了を勝手に完成させない）
- 開始と終了がそろうと横に「20分」。そろうまでは灰色の案内文
- 開始だけ選んだ時点で開始を保存する（入浴を始めた時に打って画面を閉じても残る）
- 前後の比較は日報の流れ（15:00 始まり）で行う。23:50〜0:10 は 20 分
- 終了が開始以前：赤字で知らせ、保存しない（前に保存した時刻はそのまま）
- 見出しの横に「11/23夕〜11/24朝」と、この日報が受け持つ範囲を出す（日報の日付＝朝の日付）
- 1 時間超え：保存はする。確認の注意を出す
- 同じ番号が 2 人：両方に注意を出す。止めない
- 保存ボタンなし。選ぶたびに保存し「✓ 保存しました」

## 4. 保存

表 `bath_records`（`migrations/2026-11-24_bath_records.sql`）。1 人 1 日 1 行。

| 列 | 中身 |
|---|---|
| gh_num / report_date | ホーム／日報の日付（＝朝の日付。夕方の入浴は前日の夕方） |
| resident_id か short_stay_key | 入居者か、短期入所の枠（検温と同じ持ち方） |
| resident_name | 表示用の写し |
| kind | `home`（ホームで入浴）／`facility`（事業所で入浴）／`none`（入浴なし） |
| bath_order | 順番（home の時だけ） |
| start_min / end_min | 0 時からの分・10 分刻み。開始だけ先に入る。終了は開始があってから |

- 権限は検温の表と同じ（ログイン済みだけ読み書き可・未ログインは拒否）
- 判定は `scripts/bath_logic.js` の `decide`（純粋関数・テスト `bath_logic.test.js`）
- 往復：開く時の読み込みは居室確認・検温と同時に 1 本（直列の往復は増やさない）。選ぶたびに 1 往復。同じ値は送らない
- 続けて選んだ時は 1 人ぶんを順に 1 本ずつ送り、最後の選択が残るようにする
- 日付を切り替えた隙間では書かない。表が読めない時は「入浴を読み込めませんでした」を出して選べなくする（日報は止めない）
- 「選ぶ」に戻すとその行を消す

## 5. 管理者ダッシュボード（care-stack-absence）

- `GET /report/api/bath?date=`（ログインの内側）。表が無い間は `state: missing` で 200
- 日報確認タブの一覧の下に「マハロの入浴状況」：順番・氏名・開始〜終了・かかった時間。並びは順番→事業所で入浴→入浴なし。1 時間超えは赤字。下に人数。表が無い間は枠ごと出さない
- 利用者別の月の記録：日ごとに「入浴　2番　17:30〜17:50（20分）」
- 表示の部品は `static/report/bath_view.js`（純粋関数）

## 6. 反映の順

1. 管理画面側を push（表が無い間は枠を出さないだけ）
2. 本番の日報 DB に `bath_records` を追加（Getter 本体・事前に無いことを確認）
3. 日報側を push

## 7. やらないこと

ほかのホームへの展開／事業所の名前の選び分け／1 日 2 回の入浴／Word 出力・まとめ表示への追加／平均・合計の表示。

## 8. 残っていること

- 保存に失敗した時は 3 秒おきに 3 回まで自動で送り直す。それでも駄目なら読み込み直しを案内する
- 別の端末の古い画面から選ぶと、先に入った時刻を空で上書きしうる（検温と同じ水準・実例が出たら直す）
- 「選ぶ」に戻すと確認なしで消える／短期入所は氏名を後から入れても保存済みの行の名前は変わらない／管理画面は入浴だけの変更では自動更新されない（日付を選び直すと出る）
